# GitHub och samarbete

## Varför GitHub för samarbete?

När det kommer till samarbete är GitHub en väldigt bra plats att jobba på. Det ger möjligheten för flera personer att jobba på samma kodbas samtidigt, utan att skriva över andras arbete.

Många systemutvecklare uppskattar att jobba med GitHub. Istället för att en person ska sitta med "originalfilen" kan alla jobba parallellt i sina egna branches och utveckla. När alla i samarbetet känner sig klara kan de mergea ihop sitt arbete på ett kontrollerat sätt.

## Branch (`git branch`)

En branch är en egen extra arbetsgren, där man kan jobba isolerat utan att påverka huvudversionen (main). Branch låter dig utveckla olika delar av projektet medan det finns en live-version av det fungerande projektet.

## Pull request (`git pull`)

En pull request är en funktion som hjälper till att föra över ändringar från en branch till huvudgrenen, som är "main"-branchen. Med hjälp av en pull request visas exakt vilka rader som har ändrats och vad som har ändrats. Detta ger möjligheten för personer i teamet att granska, kommentera och godkänna ändringen innan den sker i huvudversionen.

## Merge (`git merge`)

Merge är funktionen som betyder att man har slagit ihop en branch med huvudgrenen "main".

---

## Sammanfattning

| Begrepp | Betyder |
|---|---|
| **GitHub** | Plattform där flera kan samarbeta på samma kodbas parallellt |
| **Branch** | Egen arbetsgren, isolerad från huvudversionen (main) |
| **Pull request** | Föreslår ändringar från en branch till main, möjliggör granskning och godkännande |
| **Merge** | Slår ihop en branch med huvudgrenen (main) |
